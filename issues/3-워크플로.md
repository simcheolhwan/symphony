## 3-1. 인스턴스별 모델과 추론 수준 지정 `feature`

모델과 추론 수준이 워크플로 파일에 하드코딩되어 있어, 무인 실행의 토큰 사용량을 작업 종류별로 통제할 수 있도록 인스턴스 설정으로 옮긴다.

### 요구사항

- 인스턴스마다 `model`, `model_reasoning_effort`를 지정하면 그 값으로 Codex가 실행된다. 모델을 생략하면 Codex 기본값으로, 추론 수준을 생략하면 `xhigh`로 실행된다.

### 설계 결정

- 두 값은 target 레지스트리의 워크플로 항목에 두고 런처가 `SYMPHONY_MODEL`, `SYMPHONY_MODEL_REASONING_EFFORT`로 주입한다. 워크플로의 `codex.command`는 `${SYMPHONY_MODEL:+--model="$SYMPHONY_MODEL"}` 셸 확장으로 모델 미지정 시 플래그 자체를 생략한다.
- 이 셸 확장은 오케스트레이터가 `codex.command`를 argv 분해 없이 셸 문자열로 실행하고, 설정 스키마의 `$VAR` 치환이 이 필드에는 적용되지 않는 업스트림 동작에 의존한다. 업스트림이 둘 중 하나만 바꿔도 깨지므로 머지 시 확인 지점이다.
- SSH 워커 호스트에서는 `codex.command`를 원격 셸이 평가해 오케스트레이터 호스트의 주입 환경변수가 전달되지 않으므로, 모델 플래그는 경고 없이 생략되고 추론 수준은 셸 확장의 기본값으로 폴백한다. 현재 런처는 SSH 워커를 쓰지 않아 실동작 영향은 없다.
- 추론 수준 기본값은 레지스트리와 워크플로의 `${SYMPHONY_MODEL_REASONING_EFFORT:-xhigh}` 양쪽에 둔다. 런처를 거치지 않고 워크플로 파일을 직접 실행해도 같은 수준이 적용되어야 한다.
- 업스트림 예시 설정 `elixir/WORKFLOW.md`의 codex command에서도 모델 하드코딩을 제거한다. 추론 수준의 셸 확장까지 이식하지는 않아 업스트림 소유 문서의 수정을 최소화한다.

## 3-2. Workpad 환경 스탬프에 로컬 경로가 노출됨 `bug`

### 요구사항

- Workpad 코멘트의 환경 스탬프에는 저장소와 커밋만 `<repo>@<short-sha>` 형식으로 남고 로컬 경로는 남지 않는다.

### 설계 결정

- 스탬프 형식은 저장소 코드가 아니라 Workpad 절차를 소유한 `$sim-linear-workpad` 스킬의 템플릿이 구현한다. 업스트림 예시 문서 `elixir/WORKFLOW.md`의 호스트·절대경로 스탬프 서술은 실행에 쓰이지 않으므로 수정하지 않는다.
